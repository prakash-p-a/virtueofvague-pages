CVE-2026-90970 let a logged-in user escape a prompt template sandbox in self-hosted GitLab AI Gateway and run commands on the host, the second 9.9 of the same class this year.

issue 4 · 12 oct 2026

the template that ran commands: a 9.9 in GitLab AI Gateway

Jugaad is a fix that works today and breaks tomorrow. Some weeks the AI news is mostly that: quick patches on top of quick patches.

This week there is one story where the pattern is in the record, with a CVE number.

the tell

GitLab AI Gateway is the service that connects a GitLab instance to AI models. On 2 October GitLab published CVE-2026-90970, scored 9.9 out of 10.

Per GitLab’s advisory, as reported by The Hacker News, a logged-in user with Duo Agent Platform access could escape the prompt template sandbox through a specially crafted flow configuration. The result: arbitrary commands on the gateway host.

Only self-hosted gateways need to act. GitLab.com, GitLab Dedicated and instances using a GitLab-hosted gateway are covered, per GitLab.

The detail I keep rereading: in February GitLab fixed CVE-2026-1868, also 9.9, reached through a crafted flow definition. Both are template engine weaknesses (CWE-1336). The new advisory does not mention the old one.

My read: a template is code that someone else gets to write. Calling the box around it a sandbox does not make it one.

  • A 440% growth figure for blockchain dead drops, tied by its source to the launch of open Chinese AI models. A correlation dressed as a cause. Until the method is clear, I leave it.
  • Any “AI scanner found thousands of bugs” line without a count of how many were real.

the real one

If you run a self-hosted AI Gateway, this is the week’s work. Update to the fixed version for your line. GitLab lists no workaround, and the advisory gives no way to tell whether a gateway was attacked before you patched.

GitLab’s own install guide says the gateway’s JWT signing keys must be treated as sensitive credentials, and the gateway sits between your instance and your model providers. So if you cannot rule out misuse, think about what a host like that can reach.

Caveats: CISA’s note on the CVE record lists exploitation as “none” as of 2 October. The attack conditions are not described in public, so I cannot tell you how hard this is to pull off.

tools worth a look

Read on 9 October 2026. All three are open source with recent commits. Not tested by me yet. Read the code before you run it.

  • garak (9.5k stars, Apache-2.0): a scanner that probes an LLM for known weak spots.
  • PyRIT (4.6k stars, MIT): Microsoft’s framework for finding risks in generative AI systems.
  • TruffleHog (28.4k stars, AGPL-3.0): finds and verifies leaked credentials, which matters when a service holds signing keys.

the part that stays

Security angle: AI features arrive as new surfaces on old platforms, and a flow editor that lets users write templates is a code path. The 9.9 in February and the 9.9 in October point at the same door.

Human angle: “AI gateway” sounds like plumbing, so it gets patched like plumbing, late and by whoever remembers. I don’t think anyone owns it by default.

Honestly? I don’t know whether the second fix is deeper than the first. I would like to see it explained.

  2. For self-hosted GitLab AI Gateway, confirm the version against the table above.
